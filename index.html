Why we built this
[ Thesis ]

Most agents in production are blind.
We're giving them memory of the real world.

Every Fortune company is shipping AI agents now. Almost none of them have any real memory of the physical world. They don't know whether a building still stands, whether a forest burned last week, whether a crop field is stressed, whether the corridor a drone is about to fly through is clear. So they make things up. Every confident answer about a place is, in practice, a guess.

The fix isn't a bigger model. It's an Earth memory the model can cite. Real sensors, real cells, real timestamps, signed receipts. Not synthetic vibes. Not stale tiles. The ground truth itself, addressed and verifiable.

We built that twice, on the same architecture. Encoders run wherever a lens already is. Orbit, drone, vehicle, robot, fixed camera. They turn the world into compact, semantic representations. Two decoders sit on top. One open, one private. Together they form a shared, verifiable layer that agents read before they answer.

Encoders run wherever cameras live

Orbit isn't the only place a useful lens sits. Satellites, drones, vehicle cams, robot cams, fixed CCTV, telematics. The encoder is sensor-agnostic. It compresses whatever the lens sees into dense semantic vectors that travel cheap and read fast.

Two decoders, split by ownership

emem.dev is the public layer. Apache-2.0, no API keys, every read signed with ed25519 and addressed via blake3. geo.qa is the private layer. Your modalities, your tenancy, your retention. Both speak the same algebra. Both run on the same architecture.

Memory the agent can cite

Every read carries its receipt. The agent quotes a content hash; anyone can pull the same fact and verify it offline. That single property is what turns Earth memory from a feature into infrastructure. Shared, decentralised, replayable. The thing models have been missing.

[ Architecture ]

One algebra. Cell × Band × Tslot → Fact.
Every fact signed. Every read citable.

Every place on Earth gets a stable address (a cell64, ~10m on a side). Every observation about that place lands as a fact: what band, what time, what value, what receipt. Read a fact from emem.dev and it's the same algebra as reading a fact from your geo.qa tenancy. The boundary between public and private is a tenancy, not a protocol. Your agent can mix both in a single answer and cite each one.

[ Frontier ]

Where Earth memory shows up

Anywhere an AI system has to reason about a place. Some of these are encoder endpoints generating the memory. Some are decoder consumers reading it. Most do both.

Autonomous vehicles

The car already has eight cameras. Their feeds become encoder endpoints. The same vehicle then reads the surrounding cells to know what's beyond its own line of sight, citing each one before acting on it.

Robotics

Delivery, warehouse, last-mile. The robot writes what it sees back to a private tenancy and reads what its peers wrote five minutes ago. The fleet shares one memory of the building it operates in.

UAVs & drones

Pipeline corridors, farmland, post-disaster grids. Each overflight writes signed cells; the next agent that asks "did anything change in sector seven this week" gets a real, citable answer.

Aviation

Approach planning and corridor situational awareness, including in GPS-denied or low-visibility conditions. The aircraft reads the terrain memory the same way it reads weather.

Defense & security

Persistent change detection over installations and perimeters. Private tenancy means classified context never leaves; public emem.dev cells fill in the open-source layer underneath.

Mobile & edge

The phone has a camera and an MCP client. That's enough. It can be both an encoder source for whatever it's pointed at and a reader of the surrounding memory for whatever it's about to do.

Industrial & factories

Site-level context for automation: facility layout, recent change, anomaly cells. Plant cameras feed the encoder; production agents read the decoder before they decide.

Agriculture & environment

Crop stress, evapotranspiration, deforestation, mangrove change, soil moisture proxies. Public emem.dev cells cover the planet; geo.qa adds the operator's own ground truth on top.

Two decoders.

Same algebra, same receipts, different boundaries. The split is ownership, not audience. Both serve humans and agents. Most teams use both: emem.dev for the public layer of the world, geo.qa for the layer that's theirs.

Public · Apache-2.0

emem.dev

Open Earth memory protocol. Signed, free, no keys.

The shared, decentralised layer. Anyone can run a node. Anyone can read a cell. Every response carries a blake3 content hash and an ed25519 signature you can verify without us in the loop.

  • No keys, no accounts. Hit /v1/locate, /v1/recall, /v1/diff on plain HTTP, or point an MCP client at emem.dev/mcp.
  • Verifiable offline. Recompute blake3 over the canonical CBOR, verify ed25519, done. No round-trip required to trust the answer.
  • 34 bands, 1792-D voxels. Sentinel-1/2, MODIS, Copernicus DEM, JRC water, Hansen forest, Tessera, Prithvi, Galileo. Real open data, signed at rest.

Private · Your tenancy

geo.qa

Form a private memory of every place that matters to you.

For Fortune-class operators whose AI has to be right about places and times. Bring your own modalities, build your own decoder, ground your own agents. emem.dev's public memory is pre-wired in every tenant.

  • Twelve modalities in. Cameras, drones, satellites, sensors, files, OSM, MCP. SAM3 segmentation, drone telemetry, CCTV registered with lat, lon, heading, pitch, FOV.
  • 1024-D fused memory. Visual 512, semantic 384, spatial 128, geo 128, temporal 64, overlay 64. Persisted in PostgreSQL plus a Vespa vector index, scoped to your tenancy.
  • Hard tenancy boundary. Per-org filesystem scoping. Query-layer organisation filter on every read. The boundary is enforced in the codebase, not in marketing copy.
