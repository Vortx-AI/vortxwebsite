Vortx/emem.dev

The open Earth memory protocol.

  • readany fact at any place, with no key and no account
  • nameeach fact by the blake3 of its own canonical bytes: the address is the content
  • signeach answer with ed25519; check the receipt offline, trusting no server
  • citeemem:fact:<cell64>:<fact_cid>, one line anyone re-checks to the same bytes

Four calls, and you can check the answer.

  • onCubbon Park, Bengaluru: the place the home page decodes and the catalogue's own note describes

locate the place → one cell, about 10 m across

terminal
curl -s https://emem.dev/v1/locate \
  -H 'content-type: application/json' \
  -d '{"place":"Cubbon Park, Bengaluru"}'   # → defi.zb493.yiwo.zcb4e, Cubbon Park (park), Bengaluru

recall a band → signed facts, fetched from the satellite archive if new

terminal
curl -s https://emem.dev/v1/recall \
  -H 'content-type: application/json' \
  -d '{"cell":"defi.zb493.yiwo.zcb4e","bands":["indices.ndvi"]}'
# → NDVI 0.767258382642998, captured 16 Jun 2026 by Sentinel-2C, fact_cid eheadieomxr2…, one ed25519 receipt

check the bytes → their blake3 is the fact's name

terminal
curl -s -H 'accept: application/cbor' \
  https://emem.dev/v1/facts/eheadieomxr2zusgh4nx7mfisrtme23ztjiluyrfve64xoap6hka \
  | python3 -c "import sys,base64,blake3;print(base64.b32encode(blake3.blake3(sys.stdin.buffer.read()).digest()).decode().lower().rstrip('='))"
# → eheadieomxr2zusgh4nx7mfisrtme23ztjiluyrfve64xoap6hka: the same string, because the address is the content

cite the token → and catch anyone who rounds it

terminal
curl -s https://emem.dev/v1/echo_verify \
  -H 'content-type: application/json' \
  -d '{"token":"emem:fact:defi.zb493.yiwo.zcb4e:eheadieomxr2zusgh4nx7mfisrtme23ztjiluyrfve64xoap6hka","claimed_value":"0.767"}'
# → drift: rounded; the signed value is 0.767258382642998

Nine kinds of token.

name anything as emem:kind:id; each shape says what citing it proves.

  • emem:fact:one signed observation at one cell: the only shape where the same bytes reach everyone · check a live one
  • emem:cell:a bare place: an address, with nothing attached until a fact hangs on it · check a live one
  • emem:entity:one identity for one object, so two agents co-refer: a shared reference, not shared bytes · check a live one
  • emem:bundle:a set of facts under one handle: hand over a whole case, not a list of links · check a live one
  • emem:raster:a native-resolution grid over an area: a band, a composite, terrain, an embedding · check a live one
  • emem:cube:that grid over time, for change and trajectory · check a live one
  • emem:rasterset:several grids as one re-derivable set, pinned to the recipe that made them · check a live one
  • emem:trace:how a robot, drone or sensor actually ran when it made a reading, signed by the device · check a live one
  • emem:attestation:which hardware root of trust vouched for a device key; none backed by a manufacturer yet · check a live one
  • plusemem:state: (one step of an answer’s reasoning) and emem:tree: (one row of a file’s note) · all eleven, checked
